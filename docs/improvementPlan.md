# 피드백 기반 개선 계획

작성일: 2026-11-17

## 개선 방향

이벤트 ID 기반 중복 방지와 DB 대조 검증을 바탕으로 데이터 수집의 안정성과 자동화를 보완한다.
우선 이벤트 유실 방지와 요청 추적, 사용자별 실패 처리를 개선하고, 검증·집계를 정기 실행할 수 있도록 확장한다.
각 작업의 처리 결과는 로그와 요약 보고서로 남겨 확인할 수 있게 한다.

## 1. 이벤트 유실 방지

현재 [tracker.js](../frontend/src/utils/tracker.js)는 전송 실패 후 큐가 10개를 넘으면 오래된 이벤트를 버린다.
브라우저 저장소를 사용하는 것은 식별자이며, 이벤트 큐 자체는 메모리에만 있다.

- 전송 배치의 최대 10건 제한은 유지하고, 대기 이벤트는 브라우저 저장소에 보관한다.
- 새로고침·일시 장애 후 같은 event_id로 재전송하고 성공 확인 뒤 대기 기록을 제거한다.
- 4xx 거절은 이유와 함께 별도 기록하고 무한 재시도하지 않는다.
- 저장 용량·재시도 상한 정책을 정하고 조용히 버리지 않는다. JWT·비밀번호는 저장하지 않는다.
- 로그인·로그아웃·계정 전환 시 다른 계정의 이벤트로 저장되지 않도록 테스트한다.

수정 대상: [수집기](../frontend/src/utils/tracker.js), [테스트](../frontend/tests/tracker.test.mjs), [이벤트 명세](eventTracking.md).

## 2. 요청 ID로 로그 연결

- 요청마다 request_id를 부여하고 프록시가 전달한 값을 검증해 이어받는다.
- 응답·FastAPI 로그·이벤트에 같은 ID를 남기고 Nginx 로그와 대조한다.
- event_id는 이벤트, session_id는 방문, request_id는 HTTP 요청 식별자다. 서로 대체하지 않는다.

수정 대상: [FastAPI 앱](../backend/app/main.py), [이벤트 수집](../backend/app/api/routes/tracking.py), [nginx 로그 설정](../monitoring/nginx/monitoring.conf).

## 3. 사용자별 실패 격리

현재 [run_bounded](../users/playwright/safety.py)는 한 작업이 실패하면 대기 중인 작업도 멈춘다.

- 개별 사용자·시나리오 실패는 기록하고 다음 사용자를 진행한다.
- DB 장애·정합성 오류·쓰기 예산 초과는 전체 중단 정책을 유지한다.
- 실패 사용자 재시도 시 이미 생성된 예매·결제를 반복하지 않는다.

수정 대상: [공통 실행 제어](../users/playwright/safety.py), [최초 방문](../users/playwright/run.py), [추가 방문](../users/playwright/runPeriods.py).

## 4. 실행 로그와 요약 보고서

- 실행기의 print 중심 출력을 logging으로 정리한다.
- run_id, 시작·종료·소요 시간, 입력·저장·중복·거절·실패·재시도 건수를 남긴다.
- 인증정보와 원시 state.json은 제외하고 공유 가능한 요약 보고서만 Git에 보관한다.

## 5. 검증·집계 파이프라인 정기 실행

- 검증 → 일별 집계 → 요약 보고서 생성을 하나의 작업으로 묶는다.
- 스케줄러에 등록하고 중복 실행 방지·실패 기록·재시도 기준을 적용한다.
- 같은 기간을 재처리해도 집계가 중복되지 않게 한다.
- 샘플 데이터로 먼저 검증한다. 실서비스 부하·회원가입·예매 생성은 자동 정기 작업에 넣지 않는다.
